# 需求规格说明书：实验室设备预约管理器

## 1. 项目目标

开发一款本地运行的实验室设备预约管理器，用于维护设备信息、创建预约、检测时间冲突、查询预约记录并统计设备使用情况。

三名成员基于本文档独立开发，技术栈可以不同，但业务行为必须一致。

## 2. 用户角色

单机普通用户，无需注册或登录。用户可以在本地管理设备并创建预约。

## 3. 功能需求

### FR1 设备管理

- 添加设备
- 编辑设备
- 查看设备列表和设备详情
- 删除设备
- 设备至少包含编号、名称、位置、状态和可用时间段
- 设备编号不能重复

### FR2 预约管理

- 创建预约
- 查看预约列表
- 取消预约
- 预约至少包含设备、预约人、日期、开始时间、结束时间和状态
- 预约人不能为空
- 开始时间必须早于结束时间

### FR3 冲突检测

- 同一设备在同一日期存在时间重叠的有效预约时，禁止创建新预约
- 已取消预约不参与冲突判断
- 首尾相接的预约不算冲突
- 创建冲突预约时必须向用户显示明确提示

### FR4 查询与筛选

- 按设备筛选预约
- 按日期筛选预约
- 按预约状态筛选预约
- 可以组合多个筛选条件

### FR5 状态管理

预约状态包括：

- 已预约
- 使用中
- 已完成
- 已取消

状态流转必须符合数据契约。

### FR6 统计与可视化

- 显示设备总数
- 显示有效预约数量
- 显示已取消预约数量
- 按设备统计预约次数或使用时长
- 提供至少一种简单可视化，例如柱状图或分类占比图

### FR7 本地持久化

- 使用 JSON 或 SQLite 保存数据
- 程序重启后设备和预约数据不能丢失
- 数据文件位置必须在运行说明中注明

### FR8 输入校验

- 必填字段不能为空
- 设备编号不能重复
- 日期必须合法
- 时间格式必须合法
- 开始时间必须早于结束时间
- 不允许创建与有效预约冲突的记录
- 删除仍有有效预约的设备时必须阻止并提示

## 4. 非功能需求

- 可在主流桌面环境本地运行
- 技术栈不限
- 代码结构清晰，关键逻辑有必要注释
- 提供完整运行说明
- 所有核心功能可以离线使用
- 记录 AI 使用过程、错误和人工修改

## 5. MVP 时间规则

- 默认只支持单日预约
- 预约时间粒度为 30 分钟
- 时间区间按 `[开始时间, 结束时间)` 处理
- 首尾相接不算冲突
- 已取消预约不占用时间

## 6. 范围排除

- 用户注册、登录和权限系统
- 云端同步
- 多实验室、多校区
- 审批流程
- 邮件、短信或消息推送
- 支付和真实金融能力
- 二维码、扫码签到
- 多语言和复杂主题系统
